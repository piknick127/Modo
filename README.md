# v1.2 第一階段：官方搜尋與本機 PDF

## 新流程
1. 在頁首輸入模型關鍵字（例如 RG 紅異端）、品番或 JAN，開啟官方搜尋。
2. 確認等級、比例與版本，從官方商品頁下載說明書 PDF。
3. 上傳 PDF（最多 40 MB / 160 頁）；程式掃描文字層並標出可能的塗裝頁。
4. 切換頁碼，在下方頁面框選塗裝區，按「擷取框選文字」。
5. 若頁面為掃描圖或文字不足，改按「辨識圖片」使用既有 OCR。
6. 核對部位、比例與庫存候選後產生試調建議。下載紀錄保留 PDF 檔名與頁碼。

中文別名只涵蓋少量常見模型；不命中時請使用官方日文名、型號或 JAN。
候選頁是關鍵字與百分比規則，不能保證找齊。找不到時仍可查看所有頁面。
文字與 OCR 按空間區塊分組，但複雜版面仍需人工確認；百分比不等於實測跨品牌比例。
PDF 在目前瀏覽器內处理；不會上傳完整說明書到 GitHub 或建立官方文件鏡像。
PDF.js 5.4.149 從 jsDelivr 載入（含 worker、字型、CMap、WASM），首次需連網。

# Nick's Paint Lab — 模型配色助手

繁體中文、手機／Edge 可用的 GitHub Pages 靜態網頁。無需 API 金鑰或後端。

## 使用
1. 上傳配色指引 JPEG / PNG / WebP。
2. 多欄照片可拖曳框選單一欄，再按「辨識圖片」。首次需連網下載 OCR 與日文資料。
3. 校對辨識文字，每個部位空一行，例如 `胸部：ブラック(70%)+ホワイト(30%)`。
4. 系統自動產生庫存候選和未實測起始比例。選擇總量、底色與光澤，下載紀錄。

「載入你的說明書範例」是人工校對的七組配方，不是 OCR 演示結果。

## GitHub Pages 部署
建立一個專用 repository（例如 `modo-paint-guide`），上傳本資料夾的 index.html、engine.js、app.js 到 main 分支根目錄。
在 Settings → Pages → Build and deployment 選 Deploy from a branch，分支 main、資料夾 /(root)，Save。
網站通常為 https://你的帳號.github.io/modo-paint-guide/ 。此交付包本身尚未部署。

## 能力與限制
- 瀏覽器內 Tesseract.js 6.0.1 OCR，支援日英／繁中英；圖片不傳到分析伺服器。外部 CDN 會接收一般資源請求。
- 51 品項庫存由 2026-09-28 Notion 手冊確認，含助劑；可取消缺貨品項、匯出／匯入備份。
- 規則引擎支援常見中日英色名及庫存 Modo 色號。未知原廠編號（如 C68/H86）不猜測。
- 跨品牌候選沿用原比例，只作未實測探索，不是色彩科學最佳化或 AI 等色預測。未建立實測混色資料。
- 混色總和非 100%、缺料、未知色名、染料與實色混合等會停止完整用量建議，保留原文。
- 金色下地→透明黃的分層配方按施工次序呈現。
- 「少量」不偽造精確數字，需逐次微量試調；匯出用量不包含稀釋液。
- 底色／光澤僅作紀錄，尚無校準模型自動補償。
- 庫存與試片筆記只存在目前瀏覽器，不自動同步 Notion；清除瀏覽資料會移除本機設定。
- 尚未提供任意新增庫存品項 UI；新增色號須更新 engine.js，避免讓未知漆系自動混用。
- 多欄 OCR 可能串行；辨識後務必核對分組。只提供單一部位的照片效果較穩定。

## 本機開發
`python3 -m http.server 8000` 後開啟 http://localhost:8000 。
測試：`node test.cjs`。

OCR：https://github.com/naptha/tesseract.js （Apache-2.0；透過 CDN 載入，未包含第三方二進位）。
庫存來源：使用者個人手冊。配方來源：使用者上傳說明書之人工轉錄。沒有納入私人原始照片。
